# Fresh challenges and default completion voice

User direction: voice on by default, preserve an off switch, and stop returning visitors receiving the same questions. Existing full autonomy and live deployment instructions apply.

## Behavior

- Voice and master sound default on only when no saved preference exists. Existing voice-off and master-mute preferences remain off. Browser gesture restrictions still apply: loading a page does not create an audio context.
- The three approved Frank recordings remain the entire voice catalogue: Short Ball, Earned Defence and Recovery. One matching cue at completion, no speech during questions and no applause layered over speech. No recordings are generated by this release.
- A daily lesson becomes encountered when its engine starts. This is distinct from completion: abandoning a challenge earns no score or streak.
- Bare homepage visits and saved automatic-entry links choose an unseen, unfinished daily challenge. Completed lessons are excluded. Explicit lesson links continue to open that exact lesson.
- After every unfinished lesson has been encountered, Home offers a clearly labelled revisit, oldest encountered first. When all are complete, Home shows exhaustion instead of resetting the catalogue.
- Progress is re-read before choices and writes to retain changes made sequentially in other tabs. History remains local to this browser; there is no phone/iPad/account sync and clearing storage clears this history. Earlier abandoned visits were never recorded and cannot be recovered retrospectively.

## Validation

Unit coverage includes default audio, saved opt-outs, encounter/completion separation, old state migration, exhaustion, day changes and stale tabs. Browser coverage completes all three voice lessons, verifies playback/mute/replay/transcripts, then tests three unique automatic entries, deliberate replay, unfinished exhaustion and completed exhaustion. Existing sensory and app-flow checks adopt the new default. Full catalogue CI remains required.

Release verification uses the explicit fresh-challenges-build.json overlay; historical migration and feature hashes remain frozen. Physical iPhone/iPad listening and cross-device history are not claimed.
