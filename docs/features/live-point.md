# Movement-led Live Point beta

User direction: make Live Point the flagship, preserve decision-making rather
than reaction-speed gameplay, show credible consequences, and check whether the
principle is recognised on a later visit. Standing autonomy and deploy-live
authorization applies; Git and artifact verification remain required.

## Scope

Two new journeys, two decisions each, four routes per journey. The first is
`live-point-buy-time`; the changed-wing variation is `live-point-other-wing`.
The original 41 journeys remain available. The principle is “Buy yourself time.
Use it to recover.” Frank speaks that two-sentence cue after final motion.

The original short-ball proposal is implemented first with an existing wide,
low-ball situation. It gives a more defensible comparison of flight time and
recovery with the existing licensed motion and ball trajectories. This is a
bounded segment of a point, ending just after the opponent's next contact, not
a finished-point simulator. No branch fabricates a winning or losing result.

The first choice selects an existing flatter middle reply or higher crosscourt
reply from `pw_data.json`. The second selects recovery during that flight or
waiting until the opponent's contact. It changes the player's actual rendered
position; both second-choice scenes use identical ball and opponent data.
Recovery interpolates from the exact follow-through pose into the shared ready
pose using the existing procedural footwork. There is no jump at the handoff.
The annotation and comparison appear only after commitment. Alternative viewing
never changes the original answers, path, progress or completion score.

This is an authored tactical illustration. Its reply is one example, not a
prediction that this opponent must hit that ball. The flatter middle reply
remains in play and is described as a time tradeoff. The preferred answer is
specific to this low, wide arrival. It does not establish a universal rule that
high crosscourt is always preferable. No independent coaching certification is
claimed. The Pro Lens links Craig O'Shannessy's public Winning on Defense
overview; our application to recovery is editorial interpretation, not a quote
or a reconstruction of an Alcaraz point.

## Return and measurement

Returning players with completed work see an unplayed Live Point on Home, with
daily continuation alongside. New visitors retain the introductory daily entry;
Explore offers Live Point immediately. Completion of the original makes its
unseen variation eligible on a later local calendar day. Direct links and
Explore permit earlier practice. Completion and encounter history prevent
automatic repeats. State remains browser-local, with no account/device sync.

`live_point_read` retains the first response per decision, the node, day, pick,
recommended-choice flag, prerequisite, elapsed calendar days and whether the
attempt occurred on a later day. Retries cannot replace those observations.
Same-day variation practice is explicitly distinguished from a later return.
Existing lesson_start, lesson_complete, app_open, payoff_open and cue_save events
provide completion, return and inspection measures. Production-host restrictions
and anonymous identifiers remain intact.

The changed wing and reversed option order are a narrow recognition probe.
They do not demonstrate on-court transfer, causation, long-term learning or
superiority over Predict. Review first-attempt patterns, completion, next-day
return and qualitative beta feedback before expanding. A future contrast should
include an earlier, balanced arrival where controlled pressure becomes available,
so repeated testing cannot teach “always choose the higher ball.”

## Release checks

- Every route at 375, 820 (reduced motion) and 1280 pixels, Chromium and WebKit.
- Handoff continuity, distinct recovery position, identical comparison ball and
  opponent, explicit in-play ending, no unplayed winner or loss.
- Original answer preservation, silent inspection, matching voice, saved cue,
  next challenge, Home eligibility and calendar-day separation.
- Full existing catalogue regression, build fingerprint overlay, hosted artifact
  parity, staged Production inspection and live verification.
- Physical iPhone/iPad sound and perceptual listening remain unverified.

Audio provenance is in `live-point-voice.json`; the one new Frank recording is
shared intentionally between the original and variation. Historical release
fingerprints and the original 41 voice records remain unchanged.
