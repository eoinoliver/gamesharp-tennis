# Customer experience audit — 6 November 2026

Baseline: production app `48b9820608`, merge
`208f28b71c7ec9b74b5dfe7971d4dd9fbc8505eb`. Repair app: `4cb5b9d09c`.
Scope: all 63 activities inventoried (211 authored nodes), all shell surfaces,
six doubles points, sharing, three Reset routines and Frank/Lara choice.

## Confirmed repairs

- Direct, shared and automatic lesson entries had no coach control until
  completion. A compact disclosure now allows Frank or Lara before answering;
  the existing completion selector stays synchronized. Selection never overrides
  explicit mute. Frank remains the default where no preference is saved.
- The partner Reset's related doubles point said “Back to doubles” but linked
  to Reset. The label now matches; all three routines also retain the exact
  originating routine through Back, Close and completion navigation. Doubles opened
  from My Game also uses the correct My Game label. Unknown
  routine values safely return to the hub.
- After first saving a Reset reminder, removal required reloading. The removal
  control now appears immediately, disappears after verified removal, and
  reappears on a subsequent save.
- Pressure's return intention read “Split for the serve, then read the return”.
  It now reads “Read the serve, then return with margin”, keeping the player's
  role coherent. Existing reminders with the old wording display the corrected
  return intention without overwriting the saved record during a read. This
  does not change the sourced insight or recordings.

## Release assessment

These are bounded usability repairs, not a new learning-effectiveness claim.
The baseline six doubles points passed all four branches at 390 and 1280 CSS
pixels (48 complete routes). Fresh automated contexts intercepted analytics.
The first repair candidate passed 78 journey checks in both Chromium and
WebKit and on its hosted preview. The final candidate extends this to 83 checks
for existing pressure reminders and My Game return context; final local/hosted
and complete CI results belong on the PR record. Build parity passed 280 release files,
279 public files and 386 tracked source/test inputs. All 86 unit tests passed.

The known defects are not a reason to rebuild the app. Before extensive sharing,
resolve the learning consistency risk below and observe independent club players
and doubles pairs on their actual phones. Browser tests cannot establish that
people understand the court, remember a useful cue, or use it with a partner.

## Two product priorities

1. **A stable lesson takeaway.** 28 activities have different standard spoken
   and saved cues. Some are harmless compression; others narrow a conditional
   read into an instruction. For example, Open Court speaks “Watch their
   movement. Choose the space.” but saves “Hit behind the run.” Return Spot
   speaks “Read the serve. Choose your starting spot.” but saves “Back for the
   big one. In for the kick.” Review these in context and choose one canonical
   portable cue per activity. Outcome-specific voice feedback may remain
   separate, clearly identified as feedback on the player's choices.
2. **An observable partner preparation loop.** Sharing works as a private,
   answer-free link followed by an explicitly proposed plan. There is no shared
   account, delivery/read receipt, synchronized answers or agreement record.
   Those are acceptable beta boundaries. Test whether a recipient can finish,
   reply to their partner and name an agreed next-match action without help.
   Do not add accounts or shared scoring before that evidence exists.

## Audio consistency finding

All 148 Frank/Lara cue files decoded in a separate FFmpeg audit. Excluding
Reset's calmer recordings, Lara ranges from -25.1 to -14.7 LUFS (10.4 LU),
and Frank from -24.3 to -17.9 LUFS. Lara's Second Serve and First Volley: Build
are the widest contrast. Lesson playback applies a common gain, retaining the
relative difference. Audition these on an ordinary phone and calibrate levels
while keeping the selected energy. Reset uses a separate playback path and
should retain its calmer delivery. No audio was regenerated or modified.
These are file measurements, not a claim of listening through physical devices.

## Voice decision

Keep the saved selected coach consistent across lessons and Reset. A mixed
Frank/Lara default is an untested product judgment, not a technical requirement.
It could offer variety but removes a predictable coach identity. If real users
want variety, add an explicit “Both” option with stable assignment per activity;
never change voice midway through a point or Reset. No mix or new audio was
introduced in this audit. Hearing samples before choosing remains a possible
small improvement; completion already allows switching and replaying a cue.

## Other observations

- Sharpen makes My Game and Reset prominent. Reset's source context is credible
  and situation-specific; at 320 CSS pixels the start button falls below the
  first viewport. That is a pacing opportunity, not a broken control. A future
  compact repeat-use mode should keep the source available without making a
  returning player reread it.
- Fresh bare entry still starts the same serve lesson. Player level is an
  optional analytics/profile field, not adaptive content. Do not describe the
  app as personalized to ability on that basis.
- Activity counts say “played”, not “mastered”; reminders and rehearsal
  self-reports remain distinct from on-court improvement. Preserve this.
- Shared recipients get a neutral title, their own decisions and no sender
  score. The standard catalogue's informative titles and some obviously poor
  alternatives can still make questions answerable from wording. A correct
  response alone is not evidence of visual tennis recognition.
- My Game, coach selection and Reset reminders are browser-local. The app
  discloses this; it is not cross-device or offline practice storage.
